## 프로젝트 기획

기존 웹은 메뉴 탐색까지만 가능했고, 주문하려면 앱을 설치해야 해 사용자 흐름이 끊기는 문제가 있었습니다. 이 문제를 해결하는 역할로 프로젝트에 투입됐고, 이후 서비스 기획과 일정 관리, 화면설계서 작성, 프론트엔드 설계·구현까지 전 과정을 담당했습니다.

앱 설치 없이 웹에서 주문과 결제를 완료할 수 있도록 전체 사용자 흐름과 기술 구조를 설계했습니다. 출시 후에는 **결제 전환율 20%**와 앱 대비 약 **3배의 객단가**를 기록했습니다.

## 주문·인증 흐름 설계

기존 웹에서는 매장과 메뉴만 볼 수 있었고, 주문하려면 앱을 설치해야 했습니다. 주문 단계가 늘어날수록 이탈 가능성이 커졌기 때문에 **인증 시점을 결제 직전으로 지연**시켰습니다. 외부 인증 페이지를 다녀와도 장바구니와 결제 입력값이 남도록 상태를 보존했습니다.

인증을 마치고 돌아오면 재고, 가격, 매장 상태, 회원 할인을 다시 확인해 품절되거나 금액이 바뀐 경우에는 변경 내용을 반영한 뒤 결제를 계속할 수 있게 했습니다.

## 프론트엔드 아키텍처 설계

결제 기능을 구현하면서 재고, 옵션, 가격, 할인처럼 서로 영향을 주는 정책과 예외 케이스가 빠르게 늘었습니다. 이 규칙을 화면이나 상태 관리 코드에서 직접 처리하면 정책이 바뀔 때 여러 컴포넌트를 함께 수정해야 했습니다.

**FSD를 기준으로 도메인 규칙, 유즈케이스, UI의 책임을 나눴**습니다. 재고 확인, 가격 계산, 할인 적용은 상태 관리와 분리된 순수 함수로 작성했습니다. 이후 정책 변경은 도메인 로직에서 처리하고 해당 함수만 테스트할 수 있었습니다. QA 중 정책이 바뀌었을 때도 UI 변경 범위를 줄였습니다.

## 출시 성과

출시 후 웹 주문 유저의 **객단가는 앱 유저의 약 3배**였습니다. 메뉴를 장바구니에 담은 사용자 가운데 **약 20%가 결제를 마쳤습니다**. 결제한 유저의 **32%가 앱을 설치**했고, 절반 이상은 마케팅 수신에 동의했습니다.
