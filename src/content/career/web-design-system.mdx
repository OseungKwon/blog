사장님 웹, 플랫폼 웹, 백오피스에서 비슷한 UI를 각자 구현하면서 서비스마다 컴포넌트의 형태와 사용 방식이 달라지고, 디자인과 코드가 어긋나는 경우도 반복되고 있었습니다.

레거시 디자인 시스템의 개선 필요성을 제안한 것을 계기로 구축에 참여해, 디자이너·PM과 함께 **컴포넌트 정책과 공통 설계 원칙을 정의하고 Button, TextField, Dialog, Tabs, Table 등의 공통 컴포넌트를 설계·구현**했습니다.

## 확장 가능한 컴포넌트 구조 설계

같은 컴포넌트라도 서비스마다 필요한 레이아웃과 기능이 달랐기 때문에, 요구사항이 추가될 때마다 props와 조건문을 늘리는 방식으로는 공통 컴포넌트를 유지하기 어렵다고 판단했습니다.

그래서 **Headless 구조로 상태와 동작을 UI에서 분리하고, Compound Component 패턴으로 필요한 요소를 조합할 수 있도록 설계**했습니다. HTML 기본 속성, `className`, `forwardRef` 등의 사용 방식도 공통 규칙으로 정리해 서비스별 확장은 허용하면서도 컴포넌트를 사용하는 방식은 일관되게 유지했습니다.

공통 컴포넌트의 변경은 별도 PR에서 리뷰하도록 하고, 기존 컴포넌트와 신규 디자인 시스템의 영역을 구분해 기존 서비스에 영향을 주지 않으면서 단계적으로 전환할 수 있는 운영 기준도 함께 정리했습니다.

## Figma·AI 개발 워크플로우 연계

Figma와 코드에서 사용하는 컴포넌트명과 속성명이 달라, 디자인 구현 시 개발자가 적절한 컴포넌트를 다시 찾고 속성을 해석해야 했습니다. Figma MCP를 활용한 AI 개발에서도 같은 이유로 기존 공통 컴포넌트 대신 새로운 UI를 생성하는 문제가 있었습니다.

디자이너와 협업해 **Figma 속성과 코드의 props·네이밍 기준을 맞추고, Figma 컴포넌트와 실제 코드 컴포넌트를 연결하는 기준을 정리**했습니다. 이를 AI 개발 워크플로우와 연결해 디자인에 맞는 공통 컴포넌트를 더 정확하게 선택할 수 있도록 했고, **UI 개발 공수를 10% 이상 줄였습니다.**

## 대용량 테이블을 통한 확장성·성능 검증

디자인 시스템의 대표 컴포넌트로 백오피스용 대용량 테이블을 구현했습니다. 단순히 고정된 테이블 UI를 제공하기보다 **Headless Hook과 Compound Component 구조를 결합해 툴바, 헤더, 그룹핑, 무한 스크롤 등을 화면에 따라 조합할 수 있도록 설계**했습니다.

또한 `react-virtual` 기반 가상화와 메모이제이션을 적용해 화면에 필요한 행만 렌더링하도록 개선했습니다. 기존 구현과 비교한 결과 **2,000건 이상의 실데이터 기준 초기 렌더 시간을 약 2.0초에서 0.1초 미만으로 단축해 약 20배 개선**했습니다.
