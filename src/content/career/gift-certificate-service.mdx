사용자가 상품권을 구매해 선물하고, 수신자가 웹에서 선물을 확인한 뒤 앱에 등록해 사용할 수 있는 상품권·선물하기 서비스를 개발했습니다. 운영자가 상품권을 생성·발행하는 백오피스부터 B2C·B2B 수신자 웹과 앱 등록 플로우까지 상품권 관련 프론트엔드 전반을 담당했습니다.

서비스 출시 이후에도 상품권 유형 추가, 기업 대량 발송, 수신자 웹 개선, 정산 화면 구축 등 비즈니스 확장에 필요한 기능을 지속적으로 개발하고 운영했습니다.

## 상품권 발행·수신 플로우 구축

운영자가 상품권을 생성·수정하고 발행할 수 있는 백오피스와, 수신자가 웹에서 선물받은 상품권을 확인하고 앱에 등록하는 전체 플로우를 구축했습니다.

상품권 정보와 이용 조건을 쉽게 확인할 수 있도록 화면 구성을 정리하고, 등록 과정의 상태와 진행 결과를 명확하게 보여주도록 인터랙션을 개선해 수신 과정의 사용성을 높였습니다.

## B2B 대량 발송 구조 확장

기존 B2C 선물하기는 결제와 함께 주문이 생성되기 때문에 발급된 상품권 식별자를 기준으로 수신 정보를 조회할 수 있었습니다. 반면 기업이 여러 명에게 상품권을 발송하는 B2B 방식은 개별 주문 없이 수신자의 이름과 연락처를 기준으로 발행해야 해 기존 구조를 그대로 사용할 수 없었습니다.

이에 **B2C와 B2B의 수신 플로우를 분리하고, 기업 대량 발송에는 별도의 식별 체계를 적용**했습니다. 주문 정보가 없는 경우에도 수신자를 안전하게 식별하고, 웹에서 상품권을 확인한 뒤 앱 등록까지 이어질 수 있도록 구성했습니다.

백오피스에는 수신자 목록의 유효성을 검증하고 여러 사용자에게 상품권을 일괄 발송할 수 있는 기능을 추가해 기업 대상 상품권 운영까지 지원했습니다.

## 운영·정산 영역 확장

서비스가 확장되면서 시즌 상품권과 B2B 발행 유형, 판매 상태와 발송 내역 관리 기능을 지속적으로 추가했습니다. 이용안내와 약관은 클라이언트 코드에 직접 포함하던 방식에서 서버에서 관리하는 구조로 전환해, 정책이 변경될 때마다 프론트엔드를 다시 배포해야 하는 의존성을 줄였습니다.

전자금융업 시스템 분리 이후에는 **상품권 구매와 프로모션 데이터를 월별로 확인할 수 있는 정산·재무제표 화면**도 구축했습니다. 일반적인 목록형 데이터와 다른 정산 구조를 별도의 변환 로직으로 분리해, 항목이 추가되더라도 화면 전체를 수정하지 않고 대응할 수 있도록 했습니다.

이를 통해 상품권의 생성·발행부터 수신·앱 등록, 기업 대량 발송과 정산까지 이어지는 **B2C·B2B 선물 커머스 운영 기반을 구축**했습니다.

**사용 기술:** React, TypeScript, Angular, Dynamic Link, Deep Link, Web API
