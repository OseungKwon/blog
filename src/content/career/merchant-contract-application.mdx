패스오더 도입을 희망하는 사장님이 매장과 사업자, 정산·결제 정보를 입력하고 가입과 계약을 완료하는 모바일 신청서를 개발했습니다. 초기 신청서와 영업용 플로우의 프론트엔드 개발을 담당했고, 이후 개선 스프린트에서는 기존 구조를 재정비하며 개발부터 QA·배포까지 수행했습니다.

파트너지원팀과 영업팀의 실제 사용 과정에서 확인된 문제를 반영해 신청 절차와 오류 안내를 지속적으로 개선했습니다.

## 사용자 유형별 계약 플로우 설계

일반 신청서와 가오픈·영업용 신청서는 매장 생성 시점과 기존에 저장된 정보가 달라 하나의 고정된 가입 절차로 처리하기 어려웠습니다.

사용자 유형과 신청 상태에 따라 필요한 단계만 노출하고, 각 단계의 입력값을 저장해 **중단된 지점부터 이어서 작성할 수 있는 다단계 플로우**를 설계했습니다. 기존 계정이나 신청 이력이 있는 경우에도 단순히 차단하지 않고 로그인이나 기존 신청서 이어쓰기로 연결했습니다.

또한 실제 사업자 서류 기준과 입력 항목을 맞춰 접수 과정에서 발생하던 정보 불일치를 줄였습니다.

## 입력·인증 오류 UX 개선

기존 신청서는 입력 오류가 발생해도 어떤 항목이 문제인지 알기 어려워 현업 문의로 이어지는 경우가 많았습니다.

필수·선택 항목을 명확히 구분하고, 유효성 검사에 실패하면 **오류 원인을 안내한 뒤 해당 입력 필드로 자동 이동**하도록 개선했습니다. 휴대폰 인증도 발송·입력·만료·불일치·재전송 상태를 구분하고, 상황에 맞는 안내 문구와 타이머를 제공했습니다.

API 오류 역시 상황별 메시지로 구분해 사용자가 직접 해결할 수 있도록 하고, 영업 담당자도 전달받은 정보만으로 원인을 파악할 수 있게 했습니다.

## 현업 피드백 기반 리팩터링과 배포

초기 일정에 맞춰 빠르게 구현된 코드에 사용자 유형과 예외 케이스가 계속 추가되면서 상태 분기와 검증 로직이 복잡해졌습니다.

개선 스프린트에서는 **단계별 폼 상태, 저장 로직, 유효성 검사, API 오류 처리를 역할별로 분리**해 구조를 다시 정리했습니다. 파트너지원팀의 문의 내용과 영업팀의 실제 사용 경험을 바탕으로 개선 항목을 정리하고, 사용자 유형별 가입·이어쓰기·인증 플로우를 중심으로 QA를 진행했습니다.

배포 시에는 변경 사항과 오류 대응 방법을 담은 릴리즈 노트를 직접 작성해 현업 부서에 공유했고, **개선 버전 배포 당일 접수 이슈 없이 안정적으로 출시**했습니다.

**사용 기술:** React, TypeScript, Multi-step Form, Web API
