기존 회원이 비회원인 친구에게 커피 쿠폰을 보내고, 수신자가 이벤트 참여부터 앱 설치와 주문까지 이어지는 신규 사용자 획득 채널을 개발했습니다. 메인 이벤트 페이지와 카카오싱크 인증 플로우를 구현하고, 메시지와 화면 구성에 따른 전환 차이를 빠르게 확인할 수 있도록 A/B 테스트 구조를 함께 설계했습니다.

## 사용자 반응을 반영한 이벤트 개선

초기에는 발신자 정보 일부를 숨겨 수신자의 호기심을 유도했지만, 누구에게서 온 메시지인지 알기 어려워 이벤트의 의도를 오해하거나 불안함을 느끼는 사용자가 많았습니다.

사용자 반응과 전환 데이터를 바탕으로 방향을 다시 검토하고, **호기심보다 커피 쿠폰과 상품권 혜택을 명확하게 전달하는 방식으로 화면과 메시지를 개편**했습니다. 발신 정보와 혜택의 우선순위를 조정해 부정적인 반응을 줄였고, 이벤트 출시 이후 **신규 가입자 수 목표 대비 16배**를 달성했습니다.

## 실험·트래킹 환경 구축 및 전사 확장

A/B 테스트와 퍼널 분석을 위해 GA, AppsFlyer, 자체 행동 로그를 함께 사용하면서 트래킹 코드가 비즈니스 로직 곳곳에 반복적으로 들어가고, 이벤트 하나를 추가할 때마다 여러 코드를 수정해야 하는 문제가 생겼습니다.

이를 해결하기 위해 **프레임워크에 의존하지 않는 선언형 트래킹 라이브러리를 단독 설계·개발**했습니다. 마크업에 트래킹 정보를 선언하면 클릭·페이지 조회·콘텐츠 노출·스크롤 등의 이벤트를 감지하고, 어댑터를 통해 필요한 분석 도구로 전달하도록 구성했습니다.

이벤트 페이지에 먼저 적용한 뒤 다른 웹 서비스로 사용 범위가 확대됐고, **트래킹 코드 작성 공수를 약 60% 줄였습니다.** 또한 Sentry를 통해 오류와 주요 전환 흐름을 모니터링하며 트래픽이 집중되는 상황에서도 안정적으로 운영할 수 있도록 대응했습니다.

**사용 기술:** React, Next.js, TypeScript, GA, AppsFlyer, Web API, Adapter Pattern, Sentry
