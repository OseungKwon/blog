## AI 개발 절차 표준화

사내에서 AI 도구를 쓰기 시작한 뒤 개발자마다 사용 방식이 달라, 같은 요구사항에서도 개발 시간과 결과물 품질에 차이가 생겼습니다. 이를 줄이기 위해 AI 워크플로우를 구축했지만, 초기 버전은 요구사항·계획·구현 문서를 단계마다 별도로 생성했습니다. 확인해야 하는 문서가 늘면서 워크플로우 도입 전보다 개발 시간이 길어졌고, 문서를 제대로 읽지 않아 요구사항이 누락되는 문제도 자주 발생했습니다.

반복되는 문서를 통합하고, 각 단계에서 필요한 문서만 확인하도록 워크플로우를 다시 설계했습니다. 설계 문서는 AI가 일방적으로 완성하지 않고, 개발자와 대화를 통해 주요 판단을 내리도록 구성했습니다. 그 결과 작업 전에 확인하는 문서량을 기존의 **약 1/3**로 줄이면서 요구사항 확인부터 구현까지의 절차를 표준화했습니다.

## 개발 규칙 자동 검증

워크플로우로 개발 절차를 표준화했지만, AI가 프로젝트에서 사용하지 않는 패턴을 적용하거나 기존 규칙을 빠뜨리는 문제는 남았습니다.

이를 보완하기 위해 **하네스 엔지니어링**을 적용했습니다. 자동으로 검증할 수 있는 규칙은 Linter, Type Checker, PostToolUse Hook으로 검사하고, 자동 검사하기 어려운 구현 패턴은 코드 레시피로 제공했습니다.

그 결과 개선 전 동일 작업 대비 **AI 도구 실행 횟수는 34%, 작업 시간은 21%** 줄었습니다.

## Figma MCP가 놓친 컴포넌트 정보 복원

Figma MCP를 연결해도 AI가 공통 컴포넌트 대신 새 UI를 만들거나 디자인과 다른 결과를 내놓았습니다. MCP가 전달한 데이터를 확인해 보니 너비가 조금만 달라도 Figma 공통 컴포넌트로 인식되지 않았고, 반복되는 구조도 매번 전체 HTML로 전달돼 토큰을 불필요하게 사용하고 있었습니다.

Figma API와 PostToolUse Hook으로 누락된 컴포넌트 정보를 복원하고 반복 데이터를 제거했습니다. 그 결과 Figma가 AI에 전달하는 입력 데이터가 **최대 70%** 줄었습니다.
