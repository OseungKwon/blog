## AI 개발 절차 표준화

사내에서 AI 도구를 쓰기 시작한 뒤 개발자마다 사용 방식이 달라, 같은 요구사항을 전달해도 개발 시간과 결과물 품질에 차이가 생겼습니다. 개발자가 여러 문서를 먼저 읽어야 했고, 문서 내용이 서로 다르거나 요구사항을 충분히 확인하지 않은 채 개발을 시작하는 경우도 있었습니다.

AI 워크플로우를 도입해 일관된 품질의 결과물을 만들도록 개선했습니다. AI에게 요구사항을 한 번에 넘기지 않고 단계별 필수로 확인해야 하는 문서들만 생성했습니다. 이로 인해 개발자가 작업 전에 읽어야 할 문서량을 기존의 **약 1/3**로 줄었습니다.

## 개발 규칙 자동 검증

워크플로우로 개발 절차를 통일시켰지만, AI 자체의 일관성 문제로 인해 프로젝트에서 쓰지 않는 패턴을 적용하거나 기존 규칙을 빠뜨리는 등의 문제가 발생했습니다. 하네스 엔지니어링을 적용해 문서와 프롬프트로 반복해서 설명하는 대신, 공통 개발 패턴을 Linter, Type Checker, Hook으로 검사했으며, 코드 레시피를 구성해 필수적으로 따라야 하는 지침을 구성했습니다.

이 개선을 통해 같은 작업에서 **AI 도구 실행 횟수는 34%, 작업 시간은 21%** 줄였습니다.

## Figma MCP가 놓친 컴포넌트 정보 복원

Figma MCP를 연결해도 AI가 공통 컴포넌트 대신 새 UI를 만들거나 디자인과 다른 결과를 내놓았습니다. MCP가 전달한 데이터를 확인해 보니, 너비만 조금 달라져도 Fimga 공통 컴포넌트로 인식되지 않았으며 반복되는 구조도 매번 전체 HTML로 전달되어 과도하게 토큰을 소모하고 있었습니다.

Figma API와 PostToolUse Hook으로 누락된 컴포넌트 정보를 복원하고 반복 데이터를 제거했습니다. 그 결과 Figma가 AI에 전달하는 입력 데이터가 **최대 70%** 줄었습니다.
