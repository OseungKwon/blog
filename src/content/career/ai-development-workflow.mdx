## AI 개발 절차 표준화

사내에서 AI 도구를 쓰기 시작한 뒤 개발자마다 사용 방식이 달랐습니다. 같은 요구사항을 전달해도 개발 시간과 결과물 품질에 차이가 생겼습니다. 개발자가 여러 문서를 먼저 읽어야 했고, 문서 내용이 서로 다르거나 요구사항을 충분히 확인하지 않은 채 개발을 시작하는 경우도 있었습니다.

작업 순서를 바꿨습니다. AI에게 요구사항을 한 번에 넘기지 않고 단계별로 확인한 뒤, 확인된 내용으로 필요한 문서만 만들었습니다. 개발자가 작업 전에 읽어야 할 문서량은 기존의 **약 1/3**로 줄었습니다.

## 개발 규칙 자동 검증

개발 절차를 정리한 뒤에도 AI가 프로젝트에서 쓰지 않는 패턴을 적용하거나 기존 규칙을 빠뜨렸습니다. 같은 내용을 문서와 프롬프트로 반복해서 설명하는 대신, 공통 개발 패턴을 Linter, Type Checker, Hook으로 검사했습니다.

검사를 코드 작성 단계에 넣은 뒤 같은 작업에서 **AI 도구 실행 횟수는 34%, 작업 시간은 21%** 줄었습니다.

## Figma MCP가 놓친 컴포넌트 정보 복원

Figma MCP를 연결해도 AI가 공통 컴포넌트 대신 새 UI를 만들거나 디자인과 다른 결과를 내놓았습니다. MCP가 전달한 데이터를 확인해 보니, 일부 속성이 바뀐 Figma 인스턴스는 공통 컴포넌트로 인식되지 않았습니다. 반복되는 구조도 매번 전체 HTML로 전달되고 있었습니다.

Figma API와 PostToolUse Hook으로 누락된 컴포넌트 정보를 복원하고 반복 데이터를 제거했습니다. 그 결과 Figma가 AI에 전달하는 데이터는 **최대 70%** 줄었습니다. 컴포넌트 식별 정보는 별도로 복원해 AI가 기존 공통 컴포넌트를 찾을 수 있게 했습니다.
