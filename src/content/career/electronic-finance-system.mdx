전자금융거래법 개정에 따라 패스머니·상품권과 같은 선불수단과 PG 정산 데이터를 기존 서비스에서 분리해 관리해야 했습니다. 외부 통신이 제한된 환경과 공개 서비스·금융 시스템 간 분리 요건을 함께 충족하면서도, 운영자가 실제 정산 업무를 처리할 수 있는 별도 시스템이 필요했습니다.

**전자금융업 백오피스를 초기 구축부터 서비스 전반까지 담당**했고, 사장님 페이지에서 정산 관련 기능만 규정에 맞춰 안전하게 분리해 제공할 수 있도록 구조를 설계했습니다.

## 전자금융업 전용 백오피스 구축

선불수단의 충전·사용·잔액과 PG별 수수료·정산 내역을 조회하고, 지급대행 업무까지 처리할 수 있는 전용 백오피스를 구축했습니다. 금융 데이터를 다루는 화면이 빠르게 늘어나는 상황에서도 사용 방식이 달라지지 않도록 **페이지 구성과 검색 조건 관리 방식을 공통화**해 운영 화면의 일관성을 유지했습니다.

암/복호화를 적용해 민감정보를 기본 화면에서 마스킹하고, 원본 확인이 필요한 경우에만 파일로 내려받을 수 있도록 접근 경로를 분리했습니다. 다운로드 시 **사용자와 사유를 함께 기록해 접근 이력을 남기고, 파일 자체에도 암호화를 적용**해 조회 이후까지 민감정보 접근을 통제했습니다.

## 사장님 페이지 금융 기능 보안 분리

공개 웹서버인 기존 사장님 페이지가 금융 데이터를 처리하는 내부 시스템과 직접 통신할 수 없었기 때문에, 전자금융업 서버와 통신하는 별도 웹 페이지를 만들고 **필요한 영역만 iframe으로 임베드해 보여주는 구조**를 설계했습니다.

부모 페이지와 iframe은 `postMessage`를 통해 필요한 정보만 주고받도록 하고, **허용된 origin 검증과 CSP를 적용해 통신 범위를 제한**했습니다. 인증이 완료된 이후에만 전자금융업 API를 호출하도록 구성해 공개 서비스와 금융 시스템 사이의 접근 경계를 명확히 했습니다.

또한 iframe 내부 높이를 동적으로 전달해 별도의 스크롤 영역 없이 기존 사장님 페이지 안에서 자연스럽게 동작하도록 구현했습니다. 이를 통해 **기존 사용자 경험을 크게 바꾸지 않으면서도 금융 기능과 민감 데이터를 별도 시스템으로 분리**할 수 있었습니다.

전자금융업 등록에 필요한 백오피스와 금융 기능 분리 구조를 구축해, 선불수단과 정산 데이터를 규제 요건에 맞춰 운영할 수 있는 기반을 마련했습니다.
