CRM 메시지와 앱 푸시, 알림톡·친구톡에서 사용하던 Branch와 Firebase Dynamic Links 등 외부 딥링크 서비스는 실제 링크 사용량이 아닌 전체 앱 MAU를 기준으로 비용이 발생했습니다. 또한 목적지나 외부 플랫폼이 변경될 때마다 여러 채널에 흩어진 링크를 찾아 수정하고 메시지 템플릿을 다시 검수해야 했습니다.

이러한 운영 비용과 외부 서비스 의존도를 줄이기 위해 **자체 딥링크 서비스인 ‘패스링크’의 웹 페이지와 관리 백오피스를 구축**했습니다.

## 외부 딥링크를 대체하는 링크 래핑 구조 구축

CRM과 메시지 템플릿에는 실제 목적지 대신 패스링크 주소를 사용하고, 내부에서 앱·웹 목적지를 관리하는 래핑 구조를 적용했습니다.

목적지나 딥링크 플랫폼이 변경되더라도 이미 발송되거나 템플릿에 등록된 링크를 다시 교체하지 않고, **패스링크의 내부 매핑만 수정해 새로운 주소로 연결**할 수 있도록 설계했습니다. 이를 통해 외부 서비스에 분산돼 있던 링크를 하나의 시스템으로 통합하고, 플랫폼 변경 시 발생하던 링크 전수 교체와 메시지 템플릿 재검수 부담을 줄였습니다.

## OS·앱 설치 상태별 연결 처리

하나의 링크로 접속하더라도 사용자의 OS와 앱 설치 여부, 브라우저 환경에 따라 이동해야 하는 목적지가 달랐습니다.

iOS의 Universal Link와 Android의 App Link를 기반으로 앱 실행을 처리하고, 앱이 설치되지 않은 경우에는 스토어나 웹 페이지로 이동하도록 fallback 흐름을 구성했습니다. 또한 모바일·데스크톱과 인앱 브라우저 등 환경별 차이를 고려해 **사용자가 어떤 경로에서 진입하더라도 적절한 목적지로 연결될 수 있도록 예외 상황을 처리**했습니다.

앱과 도메인의 연결 설정은 Nginx에서 관리해 외부 딥링크 서비스에 의존하지 않고 자체 도메인 기반으로 앱 연결을 운영할 수 있도록 했습니다.

## 링크 운영·성과 측정 백오피스 구축

운영자가 개발자의 도움 없이 링크를 생성하고 목적지를 변경할 수 있도록 관리 백오피스를 구축했습니다. 링크의 사용 여부와 운영 기간, 앱·웹 fallback 주소를 직접 설정하고, CRM에서 반복적으로 사용하는 링크는 템플릿 단위로 관리할 수 있도록 구성했습니다.

또한 **템플릿과 개별 링크 단위로 클릭 데이터를 집계**해 어떤 메시지와 캠페인이 실제 사용자 유입으로 이어졌는지 확인할 수 있도록 했습니다. 축적된 데이터는 이후 그로스팀이 CRM 성과를 분석하고, 설치 이후 사용자 이동까지 추적하는 기능으로 확장할 수 있는 기반이 됐습니다.

이를 통해 MAU 규모에 따라 비용이 증가하던 외부 딥링크 서비스의 의존도를 낮추고, **링크 생성과 변경부터 유입 성과 확인까지 내부에서 직접 운영할 수 있는 구조**를 마련했습니다.

**사용 기술:** React, TypeScript, Nginx, Universal Links, Android App Links, Web API
